# シークレットポリシー

[English](../../secrets.md) | [简体中文](../zh-CN/secrets.md) | **日本語** | [Français](../fr/secrets.md)

デバイスのデータは、リポジトリ、ログ、既定のエクスポート、エージェントに見える出力のいずれにも入りません。このドキュメントでは、何を秘密情報とみなすか、エミュレーターが実行時にそれをどう扱うか、そして `cargo xtask secrets-check` と git のフックがどのようにそれをリポジトリから締め出すかを説明します。

## 1. 識別情報のルール

ドキュメント、テスト、ゴールデン、ログ、例、コミットメッセージ、Issue、プルリクエストのいずれにも、デバイスの次の情報を載せてはいけません。

- MAC アドレス(ベースまたは派生)
- 固有 ID
- eFuse のキャリブレーションワード
- バックアップのファイル名
- cardid の内容

例とフィクスチャには、プレースホルダーの MAC プレフィックス `02:00:00` を使います。デバイスのシリアル番号やデーモンのトークンもコピーしません。デバイスの値について話すときは、値ではなく種類と場所(`file:0x1c` の `calib_word`)を示してください。

デバイス由来のファイルはデータルート(macOS では `~/Library/Application Support/passportsim/`、Windows では `%LOCALAPPDATA%\passportsim\data\`)の下に置き、デバイス固有の部分は所有者のみがアクセスできるディレクトリに置きます。

## 2. 秘密情報とみなすもの

| データ | 既定の扱い | 明示的に有効にする方法 |
|---|---|---|
| デバイスのフラッシュのバックアップ | `--flash <path>` 以外では読み込まず、読み込むとマシンが汚染済みになる | `--flash` と `--allow-tainted` |
| 生の eFuse ダンプ(MAC、固有 ID、キャリブレーション) | 読まない。既定は `--efuse synth` | `--efuse-dump <dir>`(汚染済みになる) |
| NVS の認証情報(Wi-Fi、BLE のボンディングキー、アプリのトークン) | `inspect nvs` は名前空間、キー、型を表示し、認証情報の値は表示しない。エクスポートは NVS のページを消去する | 人による確認付きの `inspect nvs --reveal` |
| cardid パーティション `[0x356000, 0x35A000)` | エミュレーターが作るイメージでは合成パターン。表示、ログ出力、エクスポートをせず、プランナーは書き込まない | なし |
| 出力に含まれる MAC、固有 ID、キャリブレーションワード | 合成時はプレースホルダー、汚染時はマスク | 人による確認付きの `--reveal identity` |
| 実物の NFC カードのイメージ | `nfc.load` で汚染済みになる。`nfc.dump` は UID と PWD/PACK を秘匿する | `--include-secrets` |
| ライブのマイク、ブリッジしたネットワークのペイロード、外部 HCI | リプレイ用にローカルでジャーナル化し、エクスポートからは除く | `--include-secrets` |
| デーモンのトークンと起動コード | ランタイムディレクトリに所有者のみで置き、出力、ログ、成果物には含めない | なし |
| デバイスのシリアル番号、バックアップのファイル名 | リポジトリやドキュメントにコピーしない | なし |

**同梱の ROM ELF は秘密情報ではありません。** `assets/rom/esp32c3_rev101_rom.elf` と `assets/rom/esp32c3_rev3_rom.elf` は Espressif が Apache-2.0 で公開している esp-rom-elfs のリリースで、[LICENSE](../../../assets/rom/LICENSE)、[NOTICE](../../../assets/rom/NOTICE)、SHA-256 のピンを記した [pins.toml](../../../assets/rom/pins.toml) とともにコミットされています。パッケージにはこの 3 ファイルがすべて含まれます。

**公式デモのイメージはリポジトリに入りません。** `xtask package` がビルドホストのファームウェアコーパスからこれを埋め込むのは、SHA-256 がピンと一致し、MIT ライセンスの文面がある場合だけです。

**汚染を伴う読み込みは人だけが行えます。** マシンを汚染するすべての入力(cardid に 0xFF 以外のバイトや NVS の認証情報を含むイメージの `--flash`、`--efuse-dump`、実物のカードの `nfc.load`)は、人による確認を必要とするネイティブ CLI の操作で、MCP や HTTP には公開されません。

## 3. シークレットセット

何を識別情報とみなすかは、1 つの純粋関数 `pemu_api::secret_set` が決めます。リポジトリのスキャナーと実行時の秘匿処理の両方がこれを使うため、両者の判断が食い違うことはありません。

メンバーと、`secrets-check` が `hashed:<kind>` として報告する種類：

| 種類 | メンバー | 形式 |
|---|---|---|
| `mac` | ベース MAC と base+1 から base+3(Wi-Fi ステーション、soft-AP、BT、Ethernet) | コロン区切り、ダッシュ区切り、区切りなしの 16 進数、大文字と小文字、バイト反転。派生 MAC は ESP-IDF の最終バイトの折り返し形式と 48 ビットの繰り上がり形式の両方 |
| `mac_suffix` | 各 MAC の 3 バイトの NIC サフィックス | テキスト形式のみ |
| `unique_id` | eFuse BLK2 の固有 ID(128 ビット) | 生のバイトと区切りなしの 16 進数、両方のバイト順 |
| `calib_word` | BLK2 の 0 でない各キャリブレーションワード | 両方のバイト順の生の 4 バイトと、16 進テキスト |
| `backup_stem` | デバイスのバックアップファイル名の語幹 | 語幹のバイト列 |
| `cardid` | cardid ウィンドウ内の 0xFF 以外の内容 | 32 バイトのチャンクごとにハッシュ |
| `nvs_credential` | 6 バイト以上の NVS 認証情報の値 | 生のバイト、16 進数、base64。実行時のみ |
| `nfc_uid`、`nfc_pwd`、`nfc_pack` | NFC タグの UID、パスワード、パスワード確認応答 | 実行時のみ |
| `canary` | 5.6 節のランダムなカナリア | ハッシュファイルのみ |

### 3.1 誤検出の防止

ガードを信頼できる程度に静かに保つため、ビルダーは 4 バイト未満のメンバー(2 バイトの NFC PACK は 16 進テキストだけを残します)、すべてのバイトが同じメンバー、0 でないバイトが 2 つ未満のキャリブレーションワード、6 バイト未満のバックアップの語幹を除外します。派生 MAC として加えるのは base+1 から base+3 だけです。先頭 8000 バイトに NUL バイトがないファイルをテキストとみなし(git と同じルール)、テキスト専用のメンバーはテキストファイルでのみ照合します。

## 4. 汚染と秘匿

エミュレーターの実行時の動作です。

- **汚染。** 秘密情報を含む入力(2 節の一覧、またはライブブリッジ)から作られたマシンは汚染済みとなり、そのフォーク、スナップショット、ブートキャッシュのエントリも同様です。汚染済みのマシンは：
  - `--include-secrets` と人による確認コードがない限り、スナップショット、フラッシュ、成果物のエクスポートを `E_SECRET_REFUSED` で拒否します。
  - レシートに `tainted: true` と表示します。
  - ブートキャッシュをメモリ内にだけ保持します。
  - 生のメモリを扱うツール(`mem_read`、`watch`、`trace`、`inspect heap`)で、cardid ウィンドウ、NVS のページ、シークレットセットに一致する箇所をマスクします。
- **秘匿処理**は、エージェントに見えるすべてのテキストと JSON の出力、および成果物ディレクトリに書き込むすべてのファイルに適用されます。照合は値で行い、マシンのシークレットセットに一致した部分は `<MAC>` または `<SECRET>` になります。エージェント自身が指定したアドレスはそのまま残します。バイナリの成果物(btsnoop、pcap、ダンプ)も同じように書き換えます。
- **エクスポート**は cardid ウィンドウを 0xFF で埋め、NVS パーティションを消去し、eFuse のバイトを省き、ライブのジャーナルのペイロードを除きます。秘匿されたスナップショットは工場出荷時の NVS と合成の cardid でブートし、レシートにその旨を記します。
- **ログ。** テレメトリーはありません。デーモンのログは秘匿されます。クラッシュレポートには、ユーザーが求めない限り RAM やフラッシュの内容を含めません。
- **ネットワーク。** リレーとブリッジは、既定でループバック、プライベート、リンクローカル、ULA の範囲を拒否し、すべての宛先をジャーナルに記録します。

## 5. リポジトリの衛生管理

正規化し、識別情報をマスクしたテキストのゴールデンはコミットできます。その場合もチェックの対象になります。

### 5.1 `.gitignore`

[`.gitignore`](../../../.gitignore) は、ファームウェアとデバイスのデータ(`*.bin`、`*.elf`、`efuse_blk*`、`*flash*.bin`、`cardid*`、`boot_log*`、`GROUND_TRUTH*`)、実行時の成果物(`*.snap`、`*.pebundle`、`*.pcap`、`*.btsnoop`、`*.wav`、`/artifacts/`、`.passportsim/`)、ローカルの設定(`*.local.toml`、`secrets-check.toml`)を無視します。`!` のエントリで再び含めるのは、同梱の ROM ELF 2 つと、レビュー済みの少数のテスト用 ELF だけです。`git add -f` は `.gitignore` を迂回できるため、本当のガードは `xtask secrets-check` です。

### 5.2 パターンルール

パターンルールはローカルのデータを必要としません(`xtask/src/secrets/`)。

| ルール | 拒否するもの |
|---|---|
| `mac-shape` | `02:00:00` プレフィックス、すべて 0 のアドレス、グループアドレス以外の、MAC の形をしたテキスト(`:` または `-` でつないだ 16 進数 2 桁の組が 6 つ) |
| `efuse-dump` | サイズと構造が生の eFuse ブロックのダンプに一致するバイナリファイル(6.1 節) |
| `nvs-credential` | 認証情報のキーを持つ NVS パーティション |
| `cardid-window` | cardid ウィンドウ `[0x356000, 0x35A000)` を含む長さのバイナリで、その範囲に 0xFF 以外のバイトがあるもの |
| `backup-name` | デバイスのバックアップの命名パターンに一致するファイル名(6.2 節) |
| `rom-pin` | `assets/rom/` 以下にある、`assets/rom/pins.toml` でピン留めされた ELF 以外のバイナリ。または `LICENSE` か `NOTICE` がない場合のそこにあるすべてのバイナリ |

ピン留めされた ROM ELF は内容に関するルールから除外されます。パッケージ作成時には、`cardid-window` は、ビルドしたばかりの `passportsim` バイナリと `pemu_wasm.wasm` も、構造的に正しい実行ファイル(PE、ELF、Mach-O、wasm)である場合に限って除外します。どちらも 0x35A000 バイトより大きく、そのオフセットにはプログラムのコードがあるためです。フラッシュイメージの前に偽のヘッダーを付けたものは、引き続き拒否されます。

### 5.3 ハッシュルール

ハッシュルールは、パターンでは捕まえられない形(区切りなしの 16 進数、バイト配列、反転したバイト列、キャリブレーションワード、cardid のチャンク)のデバイスの値を検出します。`xtask secrets-check --init` はシークレットセットのすべてのメンバーをランダムなソルトでハッシュし、`~/.config/passportsim/secrets-check.toml`(Windows では `%APPDATA%\passportsim\secrets-check.toml`)に所有者のみの権限で書き込みます(macOS では 0700 のディレクトリ内に 0600、Windows では保護された DACL。読み込むたびに再確認します)。このファイルは：

- リポジトリに入らず、デバイスのデータを持つホストから外に出ません。
- ソルト付きの SHA-256 ハッシュとランダムなカナリアだけを保持します。
- エージェントが読んだり、表示したり、コピーしたりしてはいけません。

**出力のルール。** `secrets-check` は一致した内容、メンバーの値、ハッシュを表示しません。表示するのはルール名、`file:offset`、件数だけです。`backup-name` に該当したファイルは名前を伏せて報告します。

### 5.4 各ルールの実行場所

パターンルールはすべてのホストで実行します。ハッシュルールはデバイスディレクトリがある場所で実行し、そうしたホストはそれぞれ `--init` で自分のハッシュファイルを作ります。これはそのホストで実機への書き込みを行う前に済ませておく必要があります。

| 場所 | パターンルール | ハッシュルール |
|---|---|---|
| `cargo xtask secrets-check`(ツリーまたは `--paths`) | あり | ハッシュファイルがあれば実行。なければ注記を出してスキップ |
| pre-commit フック(`--staged`)と pre-push フック(`--hook pre-push`) | あり | あり。安全側に失敗 |
| デバイスディレクトリのあるホストでの T0 | あり | あり |
| デバイスディレクトリのないホストでの T0 | あり | なし。レシートに "pattern rules only" と記載 |
| T1 | あり | あり |

ガードはファイルの場所を既知のフォルダー(Windows)または `HOME`(macOS)からだけ決め、`PASSPORTSIM_HOME`、`PASSPORTSIM_CONFIG_DIR`、`PASSPORTSIM_DATA_ROOT` が設定されている間は、`--root` を指定しない限り実行を拒否します。上書きによってデバイスディレクトリが隠れないようにするためです。

安全側に失敗する動作：

- デバイスディレクトリがあるのにハッシュファイルがないマシンでは、フックが拒否し、`cargo xtask secrets-check --init` を実行するよう案内します。
- どのモードでも、読めない、形式が不正、または所有者のみでないハッシュファイルは拒否します。
- フックは `exec cargo xtask ...` を実行するため、cargo がない場合やビルドに失敗した場合は、チェックを飛ばさずに拒否します。

### 5.5 コマンド

```text
cargo xtask secrets-check [--root <dir>]                  scan git ls-files -co --exclude-standard
cargo xtask secrets-check [--root <dir>] --paths <files>  scan the given files
cargo xtask secrets-check [--root <dir>] --staged         what the pre-commit hook runs
cargo xtask secrets-check [--root <dir>] --hook pre-push  what the pre-push hook runs
cargo xtask hooks install [--root <dir>] [--force]        install both hooks (maintainer only)
cargo xtask secrets-check --init                          write the hash file (maintainer only)
cargo xtask secrets-check --self-test                     check the hash file (maintainer only)
```

エージェントが実行するのは最初の 4 つだけです。`--paths` の相対パスは、`--root` があればそこから、なければカレントディレクトリから解決します。

### 5.6 ガードの準備

新しいクローンでは、最初のコミットの前にメンテナーが次を行います。

1. `cargo xtask secrets-check --init` を実行します。デバイスディレクトリからシークレットセットを作り、新しいソルトとランダムなカナリアでハッシュファイルを書き込みます(読み込みが 1 つでも失敗すると何も書かないため、不完全なセットがハッシュされることはありません)。
2. `cargo xtask hooks install` を実行します。
3. `cargo xtask secrets-check --self-test` を実行します。スキャナーがすべてのメンバーの形式を検出できることを確認し、件数だけを表示します。
4. カナリアを含む一時ファイルをステージし、`git commit` が拒否されることを確認してから、ステージを外して削除します。

ワークツリーはフックを共有します。`--init` を再実行するとソルトとカナリアが置き換わるため、手順 4 を繰り返してください。

### 5.7 コミットが拒否されたとき

フックは検出ごとに 1 行(ルール、ファイル、オフセット)を表示します。その後：

1. **ガードを迂回しないでください。** `git commit --no-verify` を使わず、`core.hooksPath` を変えず、フックを編集・削除せず、ハッシュファイルに触れないでください。
2. **チェックではなく内容を直してください。**
   - ドキュメントやテストでの `mac-shape`：`02:00:00` のプレースホルダーを使います。
   - フィクスチャでの `efuse-dump` や `backup-name`：6 節に従います。
   - `cardid-window` や `nvs-credential`：そのバイナリはリポジトリに置くべきものではありません。テスト時に生成するか、データルートの下に置きます。
   - `rom-pin`：`assets/rom/` に置けるのはピン留めされた ROM ELF だけです。
   - `hashed:<kind>`：実機の値がファイルに入り込んでいます。削除し、どこから来たのかを突き止めてください。
3. **値を書かずに報告してください。** ルールと `file:offset` だけを示し、一致したバイトを引用しないでください。
4. **ハッシュファイルに関する拒否**(ない、読めない、権限が違う)はメンテナーが対応します。自分で `--init` を実行しないでください。
5. **誤検出が疑われる場合**は、ルールと `file:offset` を添えてメンテナーに伝えてください。設計上、許可リストはありません。修正はファイル名やフィクスチャの形式で行います。

## 6. フィクスチャのルール

どちらのルールにも許可リストはありません。許可リストは、本物のダンプがすり抜けうる抜け道になるからです。

### 6.1 小さなバイナリのサイズのルール

`efuse-dump` は次を拒否します。

- 24 バイトまたは 32 バイト(生の eFuse ブロック 1 つ分)のバイナリファイルで、均一な値で埋められておらず、コンテナのマジック(ELF、PNG、GIF、JPEG、gzip、zip、zstd、wasm、PDF)を持たないもの。`.bin` として保存した生の 32 バイトの SHA-256 ダイジェストも含みます。
- 336 バイト(11 ブロックすべて)のバイナリファイルで、コンテナのマジックがなく、BLK1 の MAC フィールドが 0 でないユニキャストアドレスのもの。

これらのサイズのフィクスチャはテスト時に生成するか、コンテナ形式を使ってください。ダイジェストは 16 進テキストで保存します。すべて 0x00 やすべて 0xFF の均一な埋めは問題ありません。

### 6.2 合成イメージの命名のルール

`backup-name` は、次の場合にパスを検出します(大文字と小文字を区別しません)。

- ディレクトリの要素が `passport-backups` である。
- ファイル名が `efuse_blk`、`cardid`、`boot_log`、`ground_truth` で始まる。
- ファイルが生のダンプ(`.bin`、`.img`、`.dump`、`.dmp`、`.raw`。その後に `.gz`、`.xz`、`.zst`、`.bz2`、`.zip`、`.7z` のいずれかが続いてもよい)で、語幹に `backup`、`dump`、`flash`、`full`、`efuse`、`nvs`、`cardid`、`readback`、`passport`、`4m`、`8m`、`16m` のいずれかを含む。
- パスのいずれかの要素に MAC が含まれる。区切り付きの MAC の形、または数字と英字を少なくとも 1 つずつ含む 16 進数 12 桁のトークンです(プレースホルダー、すべて 0 のアドレス、グループアドレスは除きます)。

合成イメージには、これらの語を含まない名前を付けてください。例：`synthetic_image.bin`、`seeded_card_erased.img`。同じ語は `.gitignore` にもあるため、バイナリのフィクスチャにはレビュー済みの `!` エントリも必要です。バックアップの語幹そのものは、ハッシュルールが値で照合します。

## 7. フックの対象範囲

- **pre-commit** は作業ツリーではなく、ステージされた blob をスキャンします。修正後はファイルを再度ステージしてください。
- **pre-push** は `remote..local` のすべての blob をスキャンします。リモートの先端が新しいか不明な場合は、プッシュするツリーと、どのリモート追跡参照にも含まれないコミットの blob をスキャンするため、新しいブランチを通じて履歴が漏れることはありません。手動の `--hook pre-push` は `@{upstream}..HEAD`、または `HEAD` のツリーをスキャンします。
- **インストール。** フックは `git rev-parse --git-path hooks` に置かれるため、ワークツリー間で共有されます。xtask の印がない既存のフックは、`--force` を指定しない限り残します。スクリプトは `sh` のスクリプトで、どちらのホストでも Git に付属するシェルで実行されます。
- **`--init` の入力。** デバイスディレクトリは、ローカル設定の `[paths] data_root`、なければ既定のデータルートです。バックアップは、バックアップディレクトリ直下の `.bin` ファイルです。
- **`xtask` のテスト**はデバイスとフックのモードを拒否し、空の `HOME` でスキャンするため、どのテストもデバイスのデータや本物のハッシュファイルを読めません。

## 8. デバイスの安全

**デバイスを開けるもの。**

- エミュレーター、デーモン、そのエンドポイント、CI、テスト、エージェントは、`/dev/cu.*`、`/dev/tty.*`、`COM` ポートを開かず、`esptool`、`espefuse`、`idf.py flash`、`idf.py monitor` を実行しません。
- ポートを開くのは、フィーチャー `device` 付きの `pemu-planner` だけで、それも人による確認の後に限られます(`docs/ARCHITECTURE.md` の「Flashing a real device」)。検出はポートを開かずに VID/PID で列挙します。esptool の既定のリセットはアプリをダウンロードモードにしてしまうからです。実機への書き込みはネイティブ CLI 専用で、ブラウザからは行いません。

実機での**開発用キャプチャ**(ゴールデン、プローブの実行、キャリブレーション)：

1. 最初にバックアップを取る。
2. 書き込むのはブートローダー、パーティションテーブル、アプリのセグメントだけにする。
3. cardid の範囲 0x356000 から 0x359FFF には書き込まない。
4. フラッシュ全体を消去せず、eFuse を焼かない。
5. 終わったらバックアップから Passport Keys を復元し、cardid の MD5 を比較する。

デバイスのデータをそれ以外の用途に使う場合(`--efuse-dump` など)は、デバイスの所有者の明示的な承認が必要です。

**人による確認**は、協力的なエージェントの誤ったツール呼び出しを止めるためのものです。同じユーザーのシェルを持つ悪意のあるエージェントは esptool を自分で実行できるため、確認では止められません。それには後述のガードレールで対処します。確認の経路は、優先順に次のとおりです。

1. MCP のエリシテーション。ユーザーがクライアント上で応答します。
2. デーモンが表示するネイティブのダイアログ(デスクトップセッション内)。
3. 制御端末に表示するワンタイムコード。対話的なコンソールで動くフォアグラウンドのコマンドに限ります。このコードは Web UI に表示されず、ツールの結果として返されず、ファイルにも書き込まれません。

同じ経路が、`inspect nvs --reveal`、`--reveal identity`、`--include-secrets`、汚染を伴う読み込みにも使われます。

**同梱のガードレール。** [スキル](../../../skills/passportsim/SKILL.md)と [`device-deny.json`](../../../skills/passportsim/device-deny.json)(Claude Code の `.claude/settings.json` の `permissions.deny` リスト用)は、実機に届く代表的な書き方を拒否します：`esptool`、`esptool.py`、`python -m esptool`、`py -m esptool`、仮想環境の `python.exe` のパス、`esptool.exe`、`espefuse`、`espefuse.exe`、`idf.py flash`、`idf.py -p /dev/cu.*`、`idf.py -p COM*`、`\\.\COM*` のパス。そして書き込みをプランナー経由に振り向けます。パターンのリストではあらゆるシェルや引用符の書き方を網羅できないため、このリストはベストエフォートです。**実際に強制される許可リストは、引数を解析する場所にあります。** プランナーとスキルのツールは、プロセスを起動する前に、ポートとして `socket://127.0.0.1:*` と `rfc2217://127.0.0.1:*` だけを受け付けます。

このドキュメントは、すべてのパッケージにスキルとともに同梱されます。パッケージにはリポジトリのファイルが含まれないため、そこでは `.gitignore` へのリンクは解決しません。
