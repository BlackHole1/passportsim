## 报告漏洞

请不要在公开的 issue 或 pull request 中报告安全问题。请发送邮件至 **bh@bugs.cc**，并附上：

- 问题是什么，攻击者能利用它做什么；
- 复现所需的步骤、输入或固件镜像(不要包含真实设备数据，见下文)；
- 版本(`passportsim --version`)和你的主机操作系统。

你会在 3 个工作日内收到确认，10 个工作日内收到评估结果。我们会随时告知进展，与你商定披露日期，并在修复中致谢，除非你不希望署名。

## 适用范围

模拟器会运行不受信任的固件，并且在你要求时与真实设备通信。以下边界与安全相关：

- **客户机边界。** 固件不得读写主机文件，不得访问虚拟局域网明确桥接范围之外的网络，也不得以影响其他实例的方式使主机进程崩溃。
- **守护进程。** `passportsim serve` 只监听回环地址，每个 HTTP、WebSocket 和 MCP 请求都需要仅属主可读的令牌，或网页界面的一次性启动码。任何绕过这两者的方法都是漏洞。
- **真机烧录工具。** `flash_device` 会先备份 flash，绝不写入或擦除标识设备的区域，绝不整片擦除，也绝不烧写 eFuse。任何能让它做出上述操作的输入都是漏洞。
- **机密数据。** 设备数据(MAC 地址、唯一 ID、卡片内容、flash 或 eFuse 转储、备份文件名)绝不能出现在工具输出、日志、产物、仓库或发布包中。
- **发布包。** 发布包不得包含构建机器的账户路径，也不得包含机密检查会拒绝的任何内容。

## 不在范围内

- 被模拟固件自身的缺陷，或模拟器与开发板之间的行为差异。这些属于保真度问题，请提交普通 issue。
- 需要攻击者已经以你的用户身份在主机上运行代码的攻击。
- 无限循环或耗尽自身内存的固件；`run` 可以设置时间预算。

## 报告中的设备数据

不要附带来自真实设备的 flash 转储、eFuse 转储、备份或日志。如果报告确实需要这些数据，请先说明，我们会商定私密渠道。另见 [secrets.md](secrets.md)。
