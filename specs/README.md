# `specs/`: behavior data with citations

Everything here is data, not code. It records how the ESP32-C3, the board chips and the ESP-IDF
radio blobs behave, and where each fact comes from. `cargo xtask codegen` turns the register data
into the generated tables under `crates/pemu-soc-c3/src/gen/` and `crates/pemu-core/src/`; the
other files are compiled into the crates that use them or read by `xtask`. Nothing in `specs/` is
edited to make a test pass: a row changes only together with its citation.

## Files

| Path | What it holds | Read by |
|---|---|---|
| `c3-registers.csv` | one row per register field of the ESP32-C3 blocks: offset, bit range, access type and per-scope reset value | `xtask codegen` |
| `irq-sources.toml` | interrupt sources by name and number, cross-checked against the interrupt-matrix map offsets | `xtask codegen` |
| `blocks/<block>.toml` | per-block tables: `reset_domains`, `wait`, `overrides`, `stable_read`, plus the block's fidelity class | `xtask codegen`, `xtask provenance` |
| `blocks/<chip>.toml` | the same schema for a board chip that is not an MMIO block (`flash_xmc`, `cw2017`) | `xtask codegen` |
| `timing-profiles.toml` | the `fast` and `device` timing profiles, and the calibration plan | `pemu-core` (`clock.rs`), `pemu-verify` |
| `rom-pins.toml`, `magic-pcs.toml` | per-ROM hook pins, and the unused ROM range the HLE's magic PCs live in | `pemu-loader`, `pemu-machine`, `pemu-hle` |
| `boards/cw2017-profile.toml` | the battery gauge profile the BSP expects | `pemu-board` tests |
| `st7789-boot.toml`, `es8311-sequences.toml` | the display and codec command sequences of the official firmware | `pemu-board` tests |
| `oracle-qemu-regions.toml`, `oracle-known-diffs.toml` | the QEMU oracle's region map, and the intended differences an oracle comparison excuses | `xtask oracle`, `pemu-verify` |
| `hle/idf-5.5.3/*.toml` | the radio binding profiles (`ble.toml`, `wifi.toml`), their log lines, tripwires and ELF-less symbol rules | `pemu-hle`, `pemu-radio` |
| `hle/idf-5.5.3/blob-symbols.txt` | the blob-defined symbol set, generated by `cargo xtask codegen blob-symbols` | `pemu-hle` |
| `notes/*.md` | behavior facts stated in prose; `notes/silicon-campaign.md` inventories the class C, U and `UNVERIFIED` rows the device campaign settles | people |

Each TOML file explains its own fields in its header comment. The two formats `xtask codegen`
reads are described below.

## Citations

Every row names its sources, in a `provenance` field (or the file's equivalent: `basis`,
`reason`, `cite`, `*_source`). Several sources are separated by `;`.

**Allowed sources**, each one a reader can open:

- Espressif's public documentation: the ESP32-C3 technical reference manual and datasheets.
- ESP-IDF (Apache-2.0), by path and line: `IDF hal/esp32c3/include/hal/spi_ll.h:264-268`.
- The bundled ROM ELFs.
- Probe captures on real silicon (`probes/`), by capture name and line, or by the masked fact
  (`device banner boot:0xa`).
- Tests, by name, and `specs/notes/*.md`.

**Never cite:**

- A path, file name or line number of a GPL or unlicensed source (QEMU `hw/`, esp32sim).
- A device value: a MAC, a unique ID or a calibration word.

**`UNVERIFIED`** appears literally in `provenance` (or in a `note`) for any row stated without
evidence. The generated `docs/fidelity.md` lists the open ones.

`cargo xtask provenance` enforces the rule for the block files: a header or a row of the four row
arrays without a non-empty `provenance` is a finding, and so is a value that names a restricted
source path. The full clean-room rules are in
[CONTRIBUTING.md](../CONTRIBUTING.md#clean-room).

## `c3-registers.csv`

One row per field. A register with no field rows has no entry; a register appears once per field.

| Column | Meaning |
|---|---|
| `block` | block name, exactly a `c3_devices!` row name |
| `register` | register name as ESP-IDF spells it (`UART_INT_RAW`, `SPI_MEM_CMD`) |
| `offset` | byte offset from the block base, `0x000` form |
| `field` | field name as ESP-IDF spells it |
| `shift`, `width` | bit position and width of the field inside the 32-bit register |
| `access` | the emulated access type: `RW`, `RO`, `WO`, `W1C`, `W1S`, `WT`, `SC`, `RC` |
| `access_basis` | `idf` when `idf_access` maps to `access` directly, else `UNVERIFIED` with `note` saying why |
| `reset_chip`, `reset_system`, `reset_core` | field reset value per `ResetScope`; an empty cell means the scope does not restore the field |
| `idf_access` | the raw access string of the IDF header, kept for review |
| `cite` | the IDF header line the row came from |
| `note` | free text, including every `UNVERIFIED` reason |

The CSV carries no fidelity class, no `stable_read` flag and no reset-domain mask: those are
per-block judgements and live in `blocks/<block>.toml`.

## `blocks/<block>.toml`

A block file describes one `c3_devices!` row (or one board chip). Header keys:

| Key | Required | Meaning |
|---|---|---|
| `schema` | yes | schema version, `1` |
| `block` | block files | the `c3_devices!` row name; `chip` instead, for a board chip |
| `base`, `size` | block files | the window of the `c3_devices!` row, repeated here so codegen can cross-check it |
| `bus`, `address` | chip files | the bus the chip sits on and its address on it |
| `class` | yes | the block's fidelity class: `A`, `B`, `C` or `U` |
| `milestone` | yes | the milestone that first needs the block |
| `provenance` | yes | sources for the header, same rules as a row |

Then four arrays of rows: `reset_domains`, `wait`, `overrides` and `stable_read`. Every row
carries `provenance`, and a row whose `register` belongs to another block is rejected by codegen.

### `[[reset_domains]]`: which reset scopes restore a register

```toml
[[reset_domains]]
registers = "*"                       # "*" = every register of the block, or one register name
scopes = ["chip", "system", "core"]    # the ResetScope values that restore it; [] = kept always
provenance = "IDF soc/reset_reasons.h"
```

`scopes` becomes the `ResetDomain` bit mask of `RegSpec::domain` (`Chip` 0x1, `System` 0x2,
`Core` 0x4). A later row for a named register overrides the `"*"` row of the same file.

### `[[wait]]`: busy-wait rows

```toml
[[wait]]
id = "spi2.cmd_update"                # unique across all block files, "<block>.<short name>"
kind = "wait"                         # "wait", or "tripwire" for a poll that must never terminate
seed = true                           # one of the 29 seed rows
register = "SPI_CMD"
field = "SPI_UPDATE"
trigger = "write SPI_UPDATE = 1"
expect = "read SPI_UPDATE == 0"
within = "same_access"                # or { fast = "0ms", device = "0.7ms" }
polled_at = ["spi_ll_apply_config"]   # guest symbols that poll it
images = ["official", "pk"]           # corpus images known to reach the poll; [] = none yet
milestone = "M4"
provenance = "IDF hal/esp32c3/include/hal/spi_ll.h:264-268"
```

Each row becomes a model test and, where a corpus image polls it, a hang-detector expectation. A
`kind = "tripwire"` row is the opposite: reaching it means the emulator ran code it does not
model, and the run stops with `E_STUCK` naming the row.

Codegen merges the rows of every file into `crates/pemu-soc-c3/src/gen/waits.rs`:
`pub static WAITS: [WaitSpec; WAIT_COUNT]` in file-name then row order, with `find(id)`,
`of_block(block)` and `seeds()`. A row's `block` is the `block` or `chip` of its file, so the TOML
has no `block` key. A block's model tests read `of_block`, and the hang detector takes the rows an
image polls. The table is data only; no model behavior lives in it.

`seed = true` marks one of the 29 seed rows, 28 waits plus the one tripwire. Exactly 29 rows
across all block files carry it, which codegen checks; any other row carries `seed = false`. A
seed row named after the block that polls it lives with the block that owns the register and says
so in its `provenance`: the two I2S EOF rows are in `blocks/gdma.toml`, the RTC memory CRC and
FROM_CPU rows in `blocks/system.toml`, and the flash WIP row in `blocks/flash_xmc.toml`.

### `[[overrides]]`: deliberate differences from the IDF header default

```toml
[[overrides]]
register = "GPIO_STRAP"
field = "GPIO_STRAPPING"
value = 0x0A
class = "A"                           # class of this value, not of the block
provenance = "device banner boot:0xa (device reference boot log, identity masked)"
```

For a chip file the key is `command` (a flash opcode) or `register` with a `reg` offset, and
`value` may be an array of bytes. The `overrides` rows win over the CSV reset value, so an
override is the only way a generated table differs from the imported one.

**`register = "*"`** is allowed only for a rule that holds for every register group of the block
and cannot be pinned to one register (`sensitive.toml`: a write to a locked group is ignored).
Such a row states behavior in prose: codegen rejects it with an integer `value`, and it classes no
register, so the registers no other row names stay `U` and the strict gate can still flag the
first touch of one.

**`registers = "<glob>"`** names a register array with a glob in which `*` stands for any run of
characters, so a class that belongs to all 16 data words is written once:

```toml
[[overrides]]
registers = "SPI_MEM_W*"
value = "the 64-byte data buffer of a transaction, in stream order"
class = "B"
provenance = "IDF soc/esp32c3/register/soc/spi_mem_reg.h"
```

A glob row states its behavior in prose: no integer `value` and no `field`. It must match at least
one register of the block, so a typo fails codegen. It classes only the registers no other row of
the file names: a `stable_read`, `wait` or own `overrides` row always wins. `registers = "*"` is
refused; use `register = "*"`.

**`offsets`** classes a block that has no rows in `c3-registers.csv` and therefore no `RegSpec`
table (`mmu` is a flat array of 128 entries; `sha` and `regi2c` have no field layout in the IDF
headers). Such a block's rows carry `offsets` instead, as a list or as a `{ first, last, stride }`
span:

```toml
[[overrides]]
register = "MMU entry table"
offsets = { first = 0x000, last = 0x1FC, stride = 4 }
value = "one 64 KB page mapping per entry, shared by the DROM and IROM windows"
class = "B"
provenance = "IDF soc/esp32c3/include/soc/ext_mem_defs.h and hal/esp32c3/include/hal/mmu_ll.h"
```

Codegen renders these rows into `crates/pemu-soc-c3/src/gen/classes.rs`, one module per block with
a `class_at(off)`, and the block's model answers `Peripheral::fidelity` from it. Every offset is
4-aligned and inside the block window, no two rows may class one offset differently, a row with
`offsets` carries no integer `value`, and a block that has CSV rows is refused: it names its
registers instead. An offset no row names is `U`.

### `[[stable_read]]`: registers an oracle read diff may compare

```toml
[[stable_read]]
register = "EXTMEM_CACHE_STATE"
provenance = "IDF soc/esp32c3/register/soc/extmem_reg.h: reads 1 (idle) whenever the guest can observe it"
```

The default is false, so an unclassified register never enters a read comparison. List a register
here only when its read value is a function of state the emulator models, and not of timing.

### What codegen checks and generates

`xtask/src/codegen/blocks.rs` reads every file, checks it and merges it into
`crates/pemu-soc-c3/src/gen/regs_<block>.rs`. It fails on an unknown key, a row without
`provenance`, a `class` outside A, B, C and U, a file name that does not match its `block` or
`chip`, a `base` or `size` that differs from the `c3_devices!` row, a duplicate row (a second
`reset_domains` row for the same register key, a second `stable_read` row for the same register,
two `overrides` rows with the same register, field and value, or two `wait` rows with the same
id), a `register` or `field` the block's CSV rows do not have, and any total other than 29
`seed = true` rows with exactly one `kind = "tripwire"` among them. A block with no CSV rows
(`aes`, `sha`, `rsa`, `ds`, `hmac`, the five radio windows, `regi2c`, `mmu`, `iomux`, `twai`,
`dedicated_gpio`, `world_cntl`, and the two chip files) names its registers from IDF headers or
datasheets, so only the shape of its rows is checked. `xts_aes` has CSV rows and is name-checked.

What reaches a generated `RegSpec`:

| Column | From |
|---|---|
| `domain` | the `scopes` mask of the row naming the register, else the `"*"` row, which has to agree with the per-scope reset columns of the CSV |
| `stable_read` | true for a register with a `stable_read` row |
| `class` | the `class` of the register's own `overrides` row (a `register = "*"` row classes nothing), else the block's `class` when a `reset_domains`, `wait` or `stable_read` row names the register, else the `class` of the `registers` glob row that matches it, else `U` (an untouched register counts as U) |
| `FieldSpec::reset` | the CSV column, unless an `overrides` row gives an integer `value` for that field; the register reset is then the OR of the shifted field resets again |
| `cite` | the CSV citation, then this file and the row kinds that named the register |

An `overrides` row whose `value` is prose or a byte array states behavior for the model and
changes no table. Each block table also gets two generated `RegStore` tests: reset values after a
reset of each scope, and one read and one write per field access type.

Codegen also writes `crates/pemu-soc-c3/src/gen/waits.rs` from the `[[wait]]` rows,
`crates/pemu-soc-c3/src/gen/classes.rs` from the `offsets` rows, and `docs/fidelity.md`: the class
of every block, every claim with the `provenance` that supports it, and the rows still
`UNVERIFIED`. `docs/fidelity.md` is an aggregate build output, so `.gitignore` lists it and
`--check` compares it only when one is already there.
